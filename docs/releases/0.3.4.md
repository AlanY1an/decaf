# Decaf 0.3.4

A fix for **Move sessions** after switching Claude accounts.

- Decaf now recognizes the signed-in destination when Claude's local bridge
  state still lists the previous account. This fixes a case where a valid move
  was blocked because the current account could not be confirmed.
- The current configuration and running Claude process must still agree.
  Conflicting organization records continue to block a move. Regression tests
  cover moving, Undo and identity changes between preview and execution.

Includes [PR #5](https://github.com/AlanY1an/decaf/pull/5). Support remains limited
to **local Claude Code sessions in Claude Desktop 1.52386.3**.

Choose **Settings → General → Check for Updates…**, then install and relaunch.
Sign in to the destination in Claude and refresh **Move sessions**. No reinstall
or cache reset is needed; settings and local usage history stay in place.
Versions before 0.3.1 can update using the DMG or Homebrew.

## 中文

修复切换 Claude 账号后，**Move sessions** 无法确认当前目标账号、导致迁移被拦截的
一种情况：Claude 本地 bridge 状态仍保留着上一个账号。

Decaf 仍会核对当前配置与正在运行的 Claude 进程；当前账号的组织信息冲突时继续
阻止迁移。补充了迁移、撤销和预览后身份变化的回归测试。目前仍支持 **Claude Desktop
1.52386.3 中的本地 Claude Code 会话**。

通过 **Settings → General → Check for Updates…** 下载、安装并重启，然后在 Claude
登录目标账号，刷新 **Move sessions**。无需重装或清理缓存，设置与本地用量记录保留。
0.3.1 之前的版本可通过 DMG 或 Homebrew 更新。
